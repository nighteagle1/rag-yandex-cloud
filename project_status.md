## Что сделано

**Шаг 1.** Структура репозитория, `docs/requirements.md` с порогами (верных ≥ 80%, корректных отказов ≥ 90%, ссылка в 100% ответов, hit@5 ≥ 85%), `.env.example`, `docker-compose.yml`, `requirements.txt`.

**Шаг 2.** `yandex-cloud/docs`, коммит `b54e74c8dd2e49a0355494a9a539be8ac1eca7e7`. В корпусе 453 страницы (Compute 249, Object Storage 76, VPC 63, Billing 65), ~1.36M токенов cl100k. Разметка вычищена: проверено на 30 случайных страницах и автоматическим поиском остатков. Три URL проверены, открываются. Цен в репозитории нет, они подставляются из прайс-листа на сайте; в корпусе вместо них заглушки `<цена …>`.

**Шаг 3.**
- Модель эмбеддингов `qwen/qwen3-embedding-8b` прошла тест на 5 парах. Своя пара: 0.752, лучшая чужая: 0.385. У `baai/bge-m3` отрыв меньше: 0.324 против 0.367.
- Коллекции: `yc_c1000` — 1994 точки, `yc_c500` — 3920 точек; размерность 4096, cosine.
- Проверочный поиск по трём вопросам: нужная страница на первом месте во всех трёх (прерываемая ВМ → `concepts/preemptible-vm`, счёт → `billing/concepts/bill`, статический IP → `vm-set-static-ip`).
- Инцидент: пересоздание контейнера Qdrant во время загрузки (bind-mount на Windows) испортило хранилище, 832 вектора обнулились. Qdrant переведён на именованный том, в `ingest.py` добавлен кэш векторов с пересчётом нулевых. Обе коллекции перезалиты и проверены: нулевых векторов 0.
- Фактический расход на эмбеддинги (~$0.09) выше оценки по cl100k (~$0.04): токенизатор qwen считает русский текст иначе. Для следующих оценок закладывать множитель ×2.

**Шаг 4 (частично).**
- Langflow 1.12.3 в Docker. Поток собирается скриптом `scripts/build_flow.py` через REST API с первой попытки. Экспорт лежит в `flows/answer.json`, ключей в нём нет.
- Схема: ChatInput → QdrantSearch (пользовательский компонент + OpenAI Embeddings с base URL OpenRouter) → Prompt Template (`prompts/v2.md`) → OpenAI Model (OpenRouter, t=0) → FormatAnswer (дописывает найденные URL) → ChatOutput.
- `POST /api/v1/run/<flow_id>` из Python работает: ответ за ~30 с на первом вызове, со ссылкой и списком найденных страниц. Этот вызов был сделан до перезаливки `yc_c1000`, поэтому ответ тогда был неточным.
- Промпты `prompts/v1.md` и `prompts/v2.md` написаны.

**Шаг 4, доводка (2026-09-29, вечер).**
- В `qdrant_search.py` добавлено поле `query_instruction`, `build_flow.py` заполняет его значением `common.QUERY_INSTRUCTION`.
- `tweaks` работают: `Prompt-yc004.template` (подмена шаблона дала ответ «ок») и `QdrantSearch-yc003.collection_name` (несуществующая коллекция дала 404 от Qdrant).
- Langfuse: трейсы приходят, в каждом есть узлы Chat Input, эмбеддинги, Qdrant Search, промпт, генерация и Format Answer. **Задержка приёма — несколько минут.** Старый `GET /api/public/traces` для новых организаций возвращает 410, нужен `GET /api/public/v2/observations?fromStartTime=…&toStartTime=…`.
- id трейса возвращается прямо в ответе `/run`: `outputs[0].outputs[0].results.message.session_metadata.langfuse_trace_id`.
- В `common.py` добавлена `run_flow(question, collection, prompt_text, session_id)`: ответ без списка источников, URL, `trace_id`, время.
- **Баг и исправление.** Langflow при повторной загрузке потока сбросил `model` у эмбеддингов в `''` («Model does not exist»): значение не входило в список моделей OpenAI. В `build_flow.py` поле сделано `combobox` с `options=[EMBED_MODEL]`, как у LLM. Поток пересобран, id `6dde0e3b-…`.

**Проверка после исправления.** Поток после `docker restart` Langflow отвечает, значение `model` сохраняется. URL потока совпадают с `common.search` (5 из 5 на проверочном вопросе). `run_flow` дополнительно передаёт имена моделей в `tweaks` на случай сброса.
